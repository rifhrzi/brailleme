# Jejak implementasi dan QA kapital, angka, dan bingkai otomatis

Snapshot implementasi **sebelum verifikasi APK utama final**, update **0.3.0**, 8 September 2026. Cakupan: satu kata alfabet Indonesia dasar atau satu bilangan bulat tanpa tanda, maksimal **12 karakter / 24 sel fisik**. Bingkai mengikuti sasaran pada preview; pengguna tetap menekan **Pindai** untuk mengambil foto. Dokumen ini memetakan implementasi dan pengujian; laporan APK final serta pengukuran perangkat diterbitkan terpisah.

## Parameter tracker dan pemetaan foto

- Admission maksimal **5 Hz** (selang 200 ms). Worklet `onFrame` memproses frame langsung pada thread native **ImageAnalysis** milik VisionCamera, melalui satu perpindahan runtime dari JS. Tidak memakai `useAsyncRunner` atau perpindahan kedua antar-runtime worklet. `dropFramesWhileBusy` memakai strategi native `KEEP_ONLY_LATEST`; callback yang ditolak oleh admission tetap melepas frame. Target resolusi stabil **640 x 480**, format **YUV mentah**, dan `enablePhysicalBufferRotation: false`. Ini konfigurasi permintaan, bukan klaim resolusi/FPS aktual perangkat.
- Pencarian menutup viewport nyata melalui jendela tumpang tindih **2,5:1**, dimulai dari tengah lalu bagian atas/bawah; saat target ada, konteks target diprioritaskan dengan pencarian global berkala. Kandidat perlu **dua pengamatan** dalam 500 ms, **IoU >=0,3**, dan selisih pusat baris **<=0,55 x median tinggi sel**. Sasaran baru harus **20% lebih dekat** ke pusat dan terkonfirmasi sebelum mengganti sasaran lama.
- EMA **0,35** hanya menghaluskan kotak tampilan. Crop foto menggunakan koordinat mentah. Pindai nonaktif ketika umur pengamatan **>500 ms**; kotak dibersihkan pada **800 ms**. Kelompok di batas konteks belum dianggap siap.
- [word-camera-geometry.ts](../../src/ml/word-camera-geometry.ts) memetakan frame tegak <-> sensor <-> preview dan sensor -> foto memakai transform native/crop/orientasi/mirror aktual. Buffer YUV tetap dalam orientasi sensor; `FrameConverter` menerapkan mirror dan rotasi berdasarkan metadata `frame.orientation` untuk menghasilkan gambar tegak. Pemetaan kotak memakai urutan transformasi yang sama. Perubahan orientasi tetap membatalkan target walaupun viewport persegi tidak berubah ukuran; perubahan crop native juga membatalkan hasil frame lama. [Tes geometri](../../src/ml/__tests__/word-camera-geometry.test.ts) mencakup rotasi, mirror, crop sensor, dan metadata tidak sah. Overshoot tepi maksimal **0,001 piksel** dinormalisasi untuk pembulatan float native; clipping yang lebih besar tetap ditolak.
- [word-image-processing.ts](../../src/ml/word-image-processing.ts) melokalisasi kembali sasaran pada foto dalam konteks 2,5:1 dengan **maksimal dua perluasan tambahan** (tiga inferensi). Konteks menyertakan ruang di kedua ujung dan semua sel kelompok; target hilang/ambigu atau ujung belum lengkap ditolak. [word-tracked-image.test.ts](../../src/ml/__tests__/word-tracked-image.test.ts) mencakup indikator di luar kotak awal, pemulihan kelompok lebih panjang, target hilang, sel lemah, dan pelepasan resource.
- [word-model-loader.ts](../../src/ml/word-model-loader.ts) menyediakan **dua interpreter terpisah**, untuk tracker dan foto, dengan artefak model yang sama. Mount yang meminjam interpreter tracker yang sama berbagi flag kepemilikan atomik. Mutex hanya dipakai saat mengambil kepemilikan, tidak selama inferensi. Flag per-hook mengoordinasikan admission dengan cleanup; lease menunda disposal sampai frame yang sudah diterima selesai. [Tes loader](../../src/ml/__tests__/word-model-loader.test.ts) dan tes hook memeriksa unmount/retry, dua sesi yang bertumpang tindih, serta pekerjaan lama yang masih berjalan.

Dua penyesuaian native mendasari arsitektur ini. Pada Worklets **0.10.1**, helper yang sudah dipulihkan di runtime pertama kehilangan metadata yang dibutuhkan serializer untuk perpindahan kedua. [Reproduksi berbasis sumber terpasang](../../output/update-symbols-tracking-20260908/worklet-two-hop-reproduction-v1.json) menunjukkan fungsi berubah menjadi objek pada perpindahan kedua. Karena itu pekerjaan dilakukan langsung pada thread frame VisionCamera. Reproduksi tersebut menggunakan stub factory native pada Node; hasilnya menjelaskan masalah serialisasi, bukan bukti keberhasilan kamera APK.

Pada CameraX **1.7.0-alpha02** yang terpasang, jalur rotasi buffer fisik menggabungkan matriks sensor-ke-buffer dan rotasi tambahan dalam urutan yang keliru untuk pemetaan sensor ke gambar tegak. [Pemeriksaan bytecode dan aljabar matriks](../../output/update-symbols-tracking-20260908/camerax-transform-analysis/physical-rotation-transform-algebra-v1.json), dengan [hasil javap](../../output/update-symbols-tracking-20260908/camerax-transform-analysis/ImageAnalysisAbstractAnalyzer.javap.txt), mengikat temuan ke AAR aktual. Konfigurasi buffer mentah menghindari jalur komposisi tersebut; rotasi gambar dilakukan oleh `FrameConverter` melalui metadata yang sudah didukung pemetaan TypeScript. Ini perbaikan berdasarkan sumber dan tes geometri; kesesuaian kotak pada APK final masih memerlukan pengamatan runtime. Berkas bukti `output/` tersebut berada di workspace lokal.

Build preview mencatat kode tahap kegagalan yang tetap. Jika transformasi frame gagal, satu catatan `BRAILLE_WORD_TRACKING_GEOMETRY` dapat memuat empat titik sensor, pengukuran ulang empat titik frame native saat frame masih hidup, serta batas gambar tegak dan metadata orientasi/mirror. Catatan ini mengikuti cakupan diagnostik geometri foto: tanpa piksel, teks pindai, objek native, atau URI. Build produksi tidak melakukan pengukuran tambahan atau logging ini; kegagalan diagnostik tidak menggantikan jalur retry dan pelepasan frame. Histogram runtime tetap berisi agregat saja.

**Batas kelengkapan:** parser ketat hanya memeriksa sel yang berhasil dideteksi. Model masih dapat melewatkan indikator kapital/angka, lalu menghasilkan token salah yang sah secara tata aturan. Perluasan konteks tidak membuktikan bahwa semua sel pada kertas atau di luar bidang kamera ditemukan. Kasus demikian dihitung sebagai kegagalan hasil utuh; keberhasilan parser atau kotak otomatis bukan ukuran akurasi model kapital/angka.

## Konversi piksel native dan batas buktinya

[Modul geometri](../../modules/braille-word-geometry/README.md) menambahkan `resizePixels` ke helper Nitro stateless yang dibuat pada runtime JS dan diteruskan ke worklet. [WordPixelResize.java](../../modules/braille-word-geometry/android/src/main/java/com/margelo/nitro/braillewordgeometry/WordPixelResize.java) memakai resampling bilinear antialias 22-bit, pembulatan uint8 setiap lintasan, lalu float32 RGB `[1,192,480,3]` dengan skala 0..1. Koreksi metadata BGRA hanya berlaku untuk bitmap Android Nitro yang dipin; BGRA generik tetap mengikuti urutan normal.

[Adapter Kotlin](../../modules/braille-word-geometry/android/src/main/java/com/margelo/nitro/braillewordgeometry/HybridWordPhotoGeometry.kt) membaca buffer masukan hanya selama panggilan sinkron; core menyalinnya sebelum pemrosesan. Hasil memakai direct buffer milik hasil sendiri, tanpa berbagi buffer mutable antar-panggilan. Jalur TypeScript tetap menjadi fallback/oracle, diuji oleh [word-image-resize.test.ts](../../src/ml/__tests__/word-image-resize.test.ts) dan tes gambar terlacak.

## Resep training dan provenance

[word_symbol_prepare.py](../../training/scripts/word_symbol_prepare.py) membekukan baseline dan menyusun ulang foto sel publik Angelina/DSBI menjadi urutan Indonesia dasar. Pemisahan halaman sumber dilakukan sebelum crop/komposisi; data training, validation, dan sumber eksternal dipisahkan. Transformasi bentuk sel untuk pola yang tidak tersedia tetap diberi label sintetis; ini bukan dataset foto alami kapital/angka Indonesia.

[word_symbol_train.py](../../training/scripts/word_symbol_train.py) mengevaluasi baseline dengan threshold lama yang dibekukan, lalu menjalankan **satu putaran terbatas maksimal 10 epoch**, learning rate awal **0,00002**, batch **24**. Batch **12** hanya boleh dimulai kembali dari baseline setelah percobaan batch 24 mengalami OOM. Baseline/checkpoint lama dipertahankan. Semua kandidat dievaluasi; penurunan exact accuracy atau precision hasil diterima pada kelompok legacy natural/stress menggugurkan kandidat. Kandidat terbaik dipilih memakai aturan ranking yang tersimpan, bukan jumlah epoch terbesar.

[word_symbol_replay.py](../../training/scripts/word_symbol_replay.py), [word_symbol_evidence.py](../../training/scripts/word_symbol_evidence.py), dan [replay-id.cjs](../../scripts/word-decoder-parity/replay-id.cjs) menghubungkan hasil model, threshold, decoder, fixture, sumber, dan checkpoint melalui SHA-256. Angka huruf kecil, kapital tunggal, kapital seluruh kata, angka, serta penolakan wajib dilaporkan terpisah. Keberhasilan aturan atau paritas tidak menetapkan akurasi model kapital/angka pada kertas fisik.

**Keputusan deployment:** [laporan training](../../training/evidence/braille-word-reader-v1/indonesian-symbols-baseline-20260908/checkpoint-selection.json) tetap mencatat epoch 10 sebagai pemenang ranking validation. Namun [perbandingan eksternal identik](../../training/evidence/braille-word-reader-v1/indonesian-symbols-baseline-20260908/external-baseline-comparison.json), memakai decoder v3, threshold, dan 607 fixture yang sama, menghasilkan **323/607** kata tepat untuk baseline versus **306/607** untuk kandidat. Penurunan bersih 17 hasil tepat menggagalkan promosi. [Deployment selection](../../training/evidence/braille-word-reader-v1/indonesian-symbols-baseline-20260908/deployment-selection.json) mempertahankan model baseline; riwayat sepuluh epoch dan hasil kandidat tetap utuh. Precision hasil diterima yang meningkat tidak menggantikan syarat exact accuracy tidak menurun. Tidak ada training tambahan, penyesuaian threshold, atau pemilihan ulang epoch berdasarkan set eksternal.

[verify-experimental-word-model-assets.mjs](../../scripts/verify-experimental-word-model-assets.mjs) memeriksa provenance tersebut, menghitung ulang metrik/ranking training dan veto deployment secara terpisah, memeriksa baris semantik/paritas piksel, serta mempertahankan status eksperimen internal dan `physicalCameraValidated: false`. [Regresi verifier](../../scripts/test-experimental-word-model-verifier.mjs) memutasi salinan laporan dalam memori. Pemeriksaan lengkap telah lulus pada manifest/laporan baseline aktual; perubahan sumber atau artefak setelah snapshot tetap memerlukan pemeriksaan ulang.

## Perintah verifikasi dan artefak

Jalankan dari root repository. Perintah berikut adalah prosedur pemeriksaan ulang, bukan pernyataan bahwa APK final sudah tersedia:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test -- --watch=false
npm.cmd run model:verify
node scripts/test-experimental-word-model-verifier.mjs
node scripts/word-decoder-parity/replay-id.test.cjs
python -m unittest discover -s scripts/word-android-smoke -p 'test_*.py'
```

Setelah manifest/hasil training final lolos, ekspor Android pada konfigurasi preview lokal dan bangun APK internal dari staging baru dengan JDK 17. Ikuti [verifikasi APK](../../scripts/word-android-smoke/README.md): `verify_apk.py` menyimpan hash APK/model, signing, zip alignment, versi/paket/izin, dan inventaris ABI. Kontrak saat ini adalah `com.brailleme.app`, versi **0.3.0 / kode 3**, ABI **arm64-v8a dan x86_64**, signing **Android Debug**. APK internal tidak memenuhi status distribusi produksi.

```powershell
python scripts/word-android-smoke/verify_apk.py --help
python scripts/word-android-smoke/smoke.py --help
python scripts/word-android-smoke/collect_runtime.py --serial emulator-5554 --output output/runtime-20260908 --duration 600
```

Collector memerlukan emulator yang sudah diverifikasi dan scanner preview terbuka; folder hasil harus baru/kosong. Serial selalu eksplisit. Ringkasan memuat histogram latensi tracker, durasi foto, PSS, dan timestamp presentasi. **FPS SurfaceFlinger adalah proxy komposisi tampilan**, terutama untuk TextureView, bukan FPS sensor kamera. Penghitung callback tidak mencakup seluruh drop CameraX; histogram kumulatif per mount bukan persentil tepat. Target uji adalah preview >=24 FPS dan p95 tombol-ke-hasil <=2 detik, tetapi collector selalu menetapkan `acceptanceResult: not_assessed`.

Pelaksanaan skenario dan setiap kegagalan mengikuti [protokol APK native](WORD-APK-NATIVE-SMOKE-ID.md) serta [lembar uji fisik](WORD-SCAN-SELF-TEST-ID.md). Nama/path/SHA-256 APK yang benar-benar diserahkan, hasil integritas, rekaman pengambilan, laporan ART dan runtime, serta batas bukti akhir harus ditautkan pada laporan artefak final.
