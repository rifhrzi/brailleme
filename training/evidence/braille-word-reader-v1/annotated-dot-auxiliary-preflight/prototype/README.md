# Conditional private auxiliary-dot prototype

This folder contains a proposed integration patch, not active code or an adopted training run. The 24 frozen training files and seven selector sources remain unchanged. No Torch, TensorFlow or Keras module was imported during preparation; no dataset image, model or inference was opened.

`candidate/word_dot_aux_targets.py` creates queries from the existing exact DSBI TRAIN point states. A cell contributes its six explicit mask bits only if its existing irreversible completeness flag is true, every point lies inside the fine-feature sampling hull (pixel centers x=3..479 and y=3..191), and each occupied point still survives. Absent labels come from masks, never false survival flags. Partial, unknown, mask-zero and state-free Angelina records contribute no auxiliary targets. Queries retain record, cell and slot order. Each batch is padded to its actual largest query count with ignored labels (-1); an all-unknown batch has one safe dummy query per record and zero known labels. There is no arbitrary query cap or truncation.

`candidate/word_dot_aux.py` proposes one shared 1x1 occupancy-logit head on `reader.get_layer('fpn_4').input`, the existing pre-fusion stride-4 fine backbone features. It uses the existing bilinear feature sampler and actual fractional query coordinates at origin 3/stride 4. The training wrapper references the original reader tensors and weights; it does not reconstruct a backbone or copy model weights. Its outputs are the original reader tensor and sampled occupancy logits. The auxiliary coefficient is fixed at 0.25, with its own known-point BCE denominator; the original main loss is passed unchanged with weight 1. The explicit initializer seed is fixed at 20260905.

`candidate/word_train.py` is a private modified copy. The opt-in flag routes the same generated images and main target arrays through a two-input training wrapper. Patches does not make another RNG draw, recrop images, alter source order or regenerate main labels for the auxiliary task. Validation still has no DSBI point states, so all auxiliary validation labels are ignored. The expected validation loss is the original main loss plus exactly zero auxiliary loss; actual backend accounting is still pending verification.

The original reader object is used by `WordCheckpoint` for whole-word predictions and `last.keras`, `best-word.keras` and retained epoch checkpoints. The complete training wrapper and optimizer are saved separately as `last-training.keras`. That file is not a selectable or deployable reader. The current `--resume` reader path intentionally starts a fresh optimizer and auxiliary head; resuming the full auxiliary optimizer state would require an explicit separate workflow. The selectable reader is uncompiled under the auxiliary path, so it does not misleadingly retain an unused optimizer.

The concrete diff is `integration.patch`. Only word_train and two new training helpers are included; word_model, word_data, point transforms, decoder and selector are not changed. The training source tuple becomes 26 files because the two new helpers are imported by training. No new helper is imported by word_data/word_model/word_select, so the frozen seven-file selector dependency set does not change for this patch. A future adopted run still needs its own frozen source/protocol snapshot and completed source-cycle audit.

## Verified scope

Eleven NumPy/source tests pass. They cover all 63 masks; A/B absence versus lost occupied points; an originally partial cell never regaining targets; all six hull endpoints and fractional coordinates; stable record/cell/slot correspondence; uncapped dynamic padding; empty ignored batches and a separate BCE denominator; finite/aligned input checks; and the reader checkpoint boundary. An AST-executed comparison of the actual old/new `Patches.__getitem__` methods produces identical RGB arrays, original `make_target` arrays and augmentation RNG traces with the flag off and on. That comparison uses synthetic image/augmentation adapters, not actual Pillow raster processing or dataset images.

All candidate Python files parse. `report.json` binds the sources before/after the tests, log, unchanged main sources and patch. These checks establish target semantics and a reviewable integration; they do not establish Keras runtime correctness or accuracy.
